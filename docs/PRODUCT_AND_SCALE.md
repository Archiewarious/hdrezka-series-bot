# Продукт и масштаб: до 1 000 000 пользователей

Продолжение [ARCHITECTURE.md](ARCHITECTURE.md). Здесь — что нужно изменить, чтобы бот
выдержал миллион пользователей, и как он должен выглядеть для человека, который ничего
не знает ни про HDREZKA, ни про франшизы, ни про озвучки. Факты проверены 05.09.2026.

---

## 1. Новые факты

| # | Факт | Проверка |
|---|---|---|
| F16 | **Постер есть везде**: `og:image` на странице тайтла (~30 КБ), обложка 166×250 в карточке ленты и поиска (~18 КБ) | 3 страницы, 36 карточек |

## 2. Что ломается на миллионе, а что нет

Ключевое свойство архитектуры сохраняется: **поллер не зависит от числа пользователей**.
Ломаются три вещи, и все три — про действия людей, а не про ленту.

| Компонент | 1 000 | 100 000 | 1 000 000 | Что делать |
|---|---|---|---|---|
| Поллер (лента, франшизы, озвучки) | ~80 запр./ч | ~100 | ~120 | ничего — растёт только число франшиз на суточной сверке |
| **Поиск** (каждый = запрос к сайту через один IP) | ~50/день | ~5 000/день ≈ 200/ч — **предел вежливости** | ~50 000/день — **бан IP гарантирован** | **локальный поисковый индекс** (§4): сайт только как fallback |
| **Рассылка** (30 сообщений/с всем) | мгновенно | топ-событие 10 000 получателей → 6 мин | топ-событие 100 000 → **55 мин**; 1 000 000 → 9 ч | реплики sender ×N; дайджесты; платная рассылка для горячих событий (§5) |
| Бот (ответы на действия) | 1 реплика, polling | 2 реплики, **webhook** | 3–4 реплики | webhook обязателен: `getUpdates` — один потребитель |
| Лимитер / кэш поиска в памяти процесса | ок | ломается при 2 репликах | — | общий: Redis **или** UNLOGGED-таблицы Postgres |
| PostgreSQL | 10 МБ | ~1 ГБ | **~5–10 ГБ**, 15 млн подписок | индексы уже правильные; партиции outbox по дням; pgbouncer при >5 репликах |
| Картинки | — | — | 1 000 000 × картинка/уведомление | **`file_id`**: одна загрузка на сериал, дальше бесплатно (§6) |
| Доступ к сайту | 1 туннель | 1 туннель | 1 туннель + резервный | пул выходов, ротация при 403 |

### 2.1. Цифры для миллиона (оценки; факты — лимиты Telegram и замеры ленты)

- Пользователей 1 000 000; активных в день 5–10 % → **50–100 тыс. действий/день** — для Postgres и aiogram это единицы запросов в секунду.
- Подписок 15 млн строк ≈ **2 ГБ** с индексами. Уникальных страниц с подписчиками — десятки тысяч, из них выходящих ~1–2 тыс.
- Событий «новая серия» по подписанным страницам ~100–150/день (лента: 2.3/ч по аниме, F9).
- Уведомлений/день ≈ 100 событий × средний охват 1 % (10 000) = **~1 млн строк outbox в день** → чистка/партиции обязательны.
- Отправка: 1 млн/день при 30/с = 9.3 ч чистого времени — **укладывается в сутки**, но горячее событие (100 тыс. получателей) идёт 55 минут. Приемлемо ли — решение продукта (§5.2).

## 3. Целевая архитектура

```
                Telegram ──webhook──► Caddy (TLS) ──► bot ×N (aiogram, stateless)
                                                          │
 HDREZKA ◄── туннель(и) ◄── poller ×1 (advisory lock)     │      static.hdrezka.ac ◄── напрямую
                                  │                       │            (постеры, F17)
                                  ▼                       ▼
                             PostgreSQL ◄────────────► sender ×M (SKIP LOCKED)
                             + pgbouncer (при >5 реплик)      │
                             + Redis (лимитер, кэш поиска —   ▼
                               только при ≥2 репликах бота) Telegram (30/с, file_id)
```

Что остаётся неизменным: Postgres как единственное хранилище, очередь и singleton-лок;
поллер один; sender'ы без координации. Что добавляется по мере роста — в §9.

## 4. Локальный поиск (главное изменение для масштаба)

**Проблема.** Сейчас каждый поиск — запрос к сайту. На миллионе это десятки тысяч запросов
в день через один IP: бан неизбежен, и вежливость (1 запрос / 4–6 с) делает очередь на
поиск бесконечной.

**Решение.** Собственный каталог в Postgres и поиск по нему; сайт — только когда локально
пусто.

1. **Каталог наполняется бесплатно.** Поллер уже читает 3 страницы ленты каждые 3 минуты —
   36 карточек каждая. Сейчас он заводит в `pages` только известные страницы; будет заводить
   **все** (название, url, раздел, год/страна/жанр из карточки, обложка). Это ~100 новых
   строк в день, ~40 тыс. в год — ничто. Через месяц в каталоге — всё, что выходит.
2. **Индекс.** `pg_trgm` + `unaccent`: `GIN (lower(unaccent(title)) gin_trgm_ops)` плюс
   `orig_title` (со страницы, для «one piece»). Запрос: `similarity() > 0.3`, выходящие
   первыми, затем по году. Ответ — миллисекунды, ноль запросов к сайту.
3. **Fallback.** Локально < 3 результатов → идём на сайт (с лимитом на пользователя, как
   сейчас), а **все** карточки ответа кладём в каталог — база учится на пользователях.
   Кнопка «🔍 Искать на сайте» внизу локальной выдачи — для случаев, когда человек знает,
   что тайтл существует, а каталог ещё не видел его.
4. **Ожидание.** 95 % поисков — из базы, мгновенно. Сайт — единицы запросов в час
   независимо от числа пользователей.

Побочный эффект: **группировка выдачи по франшизам** становится возможной без запросов —
каталог знает `franchise_id` для всего, что кто-то когда-то открывал.

## 5. Рассылка на миллион

### 5.1. Что уже правильно
Outbox + `SKIP LOCKED` + token bucket + склейка событий одного человека. Реплики sender
добавляются без изменений кода.

### 5.2. Горячие события
Лимит 30 сообщений/с — на бота целиком, репликами его не обойти. 100 000 получателей —
55 минут. Варианты:

| Вариант | Задержка последнему | Цена | Когда |
|---|---|---|---|
| Бесплатно, 30/с | 55 мин на 100 тыс. | 0 | по умолчанию |
| `allow_paid_broadcast` (до 1000/с) | ~2 мин | 0.1 Stars за сообщение сверх 30/с ≈ 10 000 Stars на 100 тыс. | **доступно только ботам с ≥ 100 000 активных пользователей в месяц и ≥ 100 000 Stars на балансе** (FAQ Telegram) — то есть не раньше фазы C, и только если пользователи жалуются на задержку |
| Дайджест раз в день (настройка пользователя) | до 24 ч, по выбору | 0 | снимает часть нагрузки и спама — многие предпочтут |

Честная оценка: **для уведомления о серии час задержки — нормально**; серия никуда не
убежит. Платная рассылка — опция, а не необходимость, и до 100 000 активных пользователей
она в любом случае недоступна. Telegram в том же FAQ советует растягивать рассылку на 8–12 часов.

### 5.3. Партиции outbox
При ~1 млн строк в день `DELETE` старых строк дороже, чем сброс партиции (документация
PostgreSQL, §1.4 ARCHITECTURE). `notifications` → `PARTITION BY RANGE (created_at)` по дням,
партиция создаётся заранее, старше 7 дней — `DROP`. Уникальный ключ становится
`(user_id, kind, ref_id, created_at)` — дедуп по-прежнему работает, потому что событие
`(kind, ref_id)` создаётся ровно один раз (UNIQUE в `episodes`).

## 6. Картинки в уведомлениях

Ваша идея, и она правильная: постер делает уведомление узнаваемым с первого взгляда.

- **Источник**: `og:image` со страницы (F16); для страниц, которых ещё не читали — обложка
  из карточки ленты. Хранится `pages.poster_url`.
- **Загрузка**: скачиваем **напрямую с Oracle** (F17: CDN не забанен, 0.3 с, ~30 КБ) —
  туннель не тратим. Первый раз отправляем байтами, Telegram возвращает `file_id` →
  `pages.poster_file_id`. Дальше все уведомления по этому сериалу идут по `file_id` —
  без скачивания и без загрузки. На миллионе пользователей стоимость картинок — **одна
  загрузка на сериал**, а не на сообщение.
- **Формат**: одно событие → `sendPhoto` + подпись (≤ 1024 символов) + кнопки. Несколько
  событий одному человеку → текстовый дайджест (подпись к фото слишком короткая и одна
  картинка на несколько сериалов сбивает). Порог: 1 событие — фото; 2 и больше — дайджест.
- **Настройка**: «🖼 Картинки: вкл/выкл» — компактный режим для тех, кому важен трафик.

## 7. Как этим пользуется человек

Принцип: пользователь **ничего не знает** — ни команд, ни что такое франшиза, ни зачем
озвучка. Всё показываем, ничего не заставляем выбирать, каждое действие оставляет видимый
след в чате.

### 7.1. Главное меню (постоянная клавиатура, 3 × 2)

```
┌───────────────────────┬───────────────────────┐
│  🔍 Найти             │  📋 Мои подписки      │
├───────────────────────┼───────────────────────┤
│  🆕 Новое             │  📅 Календарь         │
├───────────────────────┼───────────────────────┤
│  ⚙️ Настройки          │  ❓ Помощь            │
└───────────────────────┴───────────────────────┘
```

- **🔍 Найти** — подсказка + пример: «Напишите название: например, *слизь* или *дом дракона*.
  Можно прислать ссылку на страницу HDREZKA.»
- **📋 Мои подписки** — список (§7.5).
- **🆕 Новое** — что вышло по моим подпискам за 7 дней (§7.6). Ответ на «что я пропустил?»
  — сейчас этого нет вообще.
- **📅 Календарь** — две недели вперёд (есть).
- **⚙️ Настройки** — картинки, тихие часы, режим доставки, озвучка по умолчанию (§7.7).
- **❓ Помощь** — три абзаца + «Задать вопрос» (ссылка на вас или чат поддержки, если будет).

Меню команд Telegram («/»): `/my`, `/new`, `/calendar`, `/settings`, `/help`.

### 7.2. Первый запуск (`/start`)

```
Привет! Я сообщу, когда выйдет новая серия.

Напишите название — например, «слизь» — и выберите, за чем следить.
Можно за одним сезоном, а можно за всей франшизой: тогда расскажу
и о новых сезонах, фильмах, спин-оффах.

Кнопки внизу — всё управление. 👇
```

Три абзаца, пример, стрелка на меню. Никаких списков команд.

### 7.3. Поиск

- Локальный индекс (§4): ответ мгновенный. Заголовок «Сейчас выходит (N)» / «Нашёл (N)».
- Кнопка = `➕ Название · раздел · S×E` (есть). До 5; «Показать ещё» при большем числе.
- **Группировка по франшизе**, когда она известна: одна строка
  `🎞 Игра престолов — франшиза, 8 частей, выходят 2` вместо двух отдельных; нажатие →
  обзор франшизы (§7.4). Отдельные тайтлы — как сейчас.
- Внизу: `🔍 Искать на сайте` — когда локально пусто или мало.
- Пустая выдача: почему пусто и что делать (есть).
- Нажатая кнопка → `✓`, карточка отдельным сообщением (есть).

### 7.4. Карточка сериала и обзор франшизы

Карточка (есть) + постер сверху (`sendPhoto` при первом показе, дальше `file_id`):

```
[постер]
Найдено: О моём перерождении в слизь [ТВ-4] · аниме
Сейчас: 4 сезон, 21 серия
Следующая серия: сб 12 сен · через 7 дн.
Озвучек: 5

[ ➕ Подписаться на этот сезон ]
[ 🎞 Вся франшиза «О моём перерождении в слизь» (8) ]
[ 📅 Расписание серий ]   [ ▶ Открыть на сайте ]
```

Обзор франшизы (есть): состав с статусами, «✅ Подписаться на всю», «➕» на выходящие.
Добавить: у частей без данных — не «данных пока нет», а «ещё не смотрели» + автодочитывание
трёх верхних частей при первом открытии обзора (3 запроса, один раз на франшизу — данные
тут же появятся у всех следующих пользователей).

### 7.5. Мои подписки

- Сортировка: выходящие первыми, затем по ближайшей дате, завершённые внизу.
- Строка: `📺 Слизь [ТВ-4] · 4×21 · след. 12 сен · озвучка: любая`.
- Страницы по 10 с «‹ ›», если подписок больше.
- Кнопки в строке: `🎙` (озвучка) · `📅` (расписание) · `❌`. Отписка — с подтверждением
  одним нажатием на ту же кнопку («❌ Точно?»), а не всплывашкой.
- Пусто: «Подписок нет. Напишите название — например, *слизь*.»

### 7.6. 🆕 Новое (добавить)

Серии по моим подпискам за последние 7 дней, новые сверху:

```
🆕 За неделю

сегодня
  • Слизь [ТВ-4] — 4×21 · DEEP, AniLibria, +3        ▶
вчера
  • Дом Дракона — 3×8 · LostFilm                     ▶
```

Данные уже есть (`episodes`, `episode_voices`). Кнопка `▶` — прямая ссылка на серию (§7.8).

### 7.7. ⚙️ Настройки (добавить)

```
⚙️ Настройки
🖼 Картинки в уведомлениях: вкл
🌙 Тихие часы: 23:00–08:00 (МСК)      ← в это время не пишем, отправим утром
📨 Доставка: сразу | дайджест раз в день в 20:00
🎙 Озвучка по умолчанию: любая        ← применяется к новым подпискам
🎬 Документалки и спешлы во франшизах: показывать | скрывать   (позже — нужна классификация)
```

Часовой пояс: Telegram его не отдаёт — спрашиваем один раз кнопками (МСК по умолчанию,
±). Тихие часы и дайджест реализуются в sender'е одним условием на `next_attempt_at`.

### 7.8. Уведомления (главный экран продукта)

**Одна серия** — фото + подпись + кнопки:

```
[постер]
🎬 О моём перерождении в слизь [ТВ-4]
4 сезон, 22 серия · вышла в озвучке DEEP

[ ▶ Смотреть 4×22 ]      ← url#t:509-s:4-e:22 — сразу нужная серия и озвучка (F18)
[ 🎙 Другие озвучки ]     ← список, что уже есть; остальные — «сообщу»
[ 🔕 Не следить ]
```

**Несколько серий** одному человеку — дайджест без фото:

```
🆕 Вышли новые серии

• Слизь [ТВ-4] — 4×22 (DEEP)                 ▶
• Дом Дракона — 3×9 (LostFilm)               ▶
• Ван-Пис — 22×1176 (Animedia)               ▶
```

**Новая часть франшизы:**

```
[постер новой части]
🆕 Новая часть франшизы «Мастера меча онлайн»
Безответная бабочка · фильм · 2026

[ ▶ Открыть ]   [ ➕ Следить за этой частью ]   [ 🔕 Не следить за франшизой ]
```

Правила текста: название жирным один раз; сезон×серия цифрами; озвучка — только если
известна; ссылки — кнопками, не текстом; никаких «успешно», «пожалуйста», восклицаний.

### 7.9. Ссылка «Смотреть» ведёт прямо на серию

F18: `{url}#t:{translator}-s:{season}-e:{episode}`. Озвучка — та, что выбрал пользователь;
если «любая» — та, в которой серия появилась первой (из `episode_voices`), иначе
`default_translator` страницы. Человек нажимает и сразу смотрит, не ищет сезон в плеере.

### 7.10. Рост: ссылка «поделиться»

`t.me/HDRezkaSeriesBot?start=p_88337` открывает карточку сериала — в карточке кнопка
`🔗 Поделиться` даёт эту ссылку. Друг подписывается в одно нажатие. Это дешёвый канал роста
и он же — способ подписать людей из чатов, где обсуждают выход серий.

### 7.11. Тон и мелочи

- Всё, что можно показать, — показываем; всё, что можно не спрашивать, — не спрашиваем.
- Нажатие всегда меняет сообщение или присылает новое — тост только как дубль.
- Даты — с днём недели и «через N дн.»; прошедшие — «вчера», «N дн. назад» (исправлено).
- Ошибки — что случилось и что делать: «Сайт отвечает медленно — попробуйте через пару
  минут», не «ошибка».
- Кнопки ≤ 40 символов, названия обрезаются с «…».
- Единый словарь значков: 📺 сериал · 🎞 франшиза · 🎙 озвучка · 📅 даты · 🆕 новое ·
  ▶ смотреть · ❌ убрать · ✓ сделано.

## 8. Изменения в данных

```sql
-- картинки и поиск
ALTER TABLE pages ADD COLUMN orig_title TEXT, ADD COLUMN poster_url TEXT, ADD COLUMN poster_file_id TEXT,
                  ADD COLUMN meta_line TEXT;          -- «2026, Япония, Фэнтези» из карточки
CREATE EXTENSION pg_trgm; CREATE EXTENSION unaccent;
CREATE INDEX pages_title_trgm ON pages USING gin (lower(title) gin_trgm_ops);
CREATE INDEX pages_orig_trgm  ON pages USING gin (lower(coalesce(orig_title,'')) gin_trgm_ops);

-- настройки пользователя
ALTER TABLE users ADD COLUMN photos BOOLEAN NOT NULL DEFAULT TRUE,
                  ADD COLUMN tz_offset SMALLINT NOT NULL DEFAULT 3,       -- часы от UTC, МСК
                  ADD COLUMN quiet_from SMALLINT, ADD COLUMN quiet_to SMALLINT,
                  ADD COLUMN digest_hour SMALLINT,                          -- NULL = сразу
                  ADD COLUMN default_voice_filter INTEGER[];

-- outbox партициями по дням (при >100 тыс. пользователей)
-- notifications PARTITION BY RANGE (created_at); UNIQUE (user_id, kind, ref_id, created_at)
```

Всё — через Alembic-миграции; данные не теряются.

## 10. Решения (приняты 05.09.2026 по рекомендациям)

| # | Решение |
|---|---|
| 1 | Картинки: **фото** для одной серии, **текстовый дайджест** для нескольких |
| 2 | Главное меню **3×2**: Найти · Мои подписки / 🆕 Новое · Календарь / ⚙️ Настройки · Помощь |
| 3 | **Локальный поиск** (pg_trgm + unaccent), каталог наполняется из ленты; сайт — только fallback |
| 4 | Задержка горячих уведомлений **до часа принимается**; платная рассылка — не раньше 100k MAU и только по жалобам |
| 5 | Тихие часы **включены по умолчанию, 23:00–08:00 МСК**, отключаются в настройках (ночное сообщение хуже утреннего) |
| 6 | Порядок фазы A: **картинки + прямые ссылки → Новое → Настройки → локальный поиск → поделиться → бэкапы → публикация** |
