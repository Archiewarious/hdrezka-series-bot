## Работает в проде (@HDRezkaSeriesBot)

Поиск (только выходящие, раздел в кнопке) → подписка на сезон или франшизу (обзор состава
перед подпиской) → выбор озвучек → расписание и календарь → уведомления о серии, озвучке,
новой части франшизы (все три пути проверены end-to-end) → уведомление с постером (фото для одной
серии, дайджест для нескольких) и кнопками «▶ Смотреть S×E» (прямо на серию и озвучку), «🎙 Другие
озвучки», «🔕 Не следить» с подтверждением → завершённость сезона по расписанию (сайт помечает «Завершен»
не все; в поиске такие сезоны скрыты, вместо них строка «🎞 Франшиза») → главное меню 2×2+1 → защита
(лимиты, только путь из ссылки, только личные чаты, глобальный обработчик ошибок) →
Alembic, ротация логов, graceful shutdown, systemd-туннель с iptables.

Правило: **технические сообщения в Telegram не отправляются никогда** — только логи и /stats.

## Решения приняты (05.09.2026, «по рекомендациям»)

| # | Решение |
|---|---|
| 1 | Картинки: **фото** для одной серии, **текстовый дайджест** для нескольких |
| 2 | Главное меню **3×2**: Найти · Мои подписки / 🆕 Новое · Календарь / ⚙️ Настройки · Помощь |
| 3 | **Локальный поиск** (pg_trgm + unaccent), каталог наполняется из ленты; сайт — только fallback |
| 4 | Задержка горячих уведомлений **до часа принимается**; платная рассылка — не раньше 100k MAU и только по жалобам |
| 5 | Тихие часы **включены по умолчанию, 23:00–08:00 МСК**, отключаются в настройках (ночное сообщение хуже утреннего) |
| 6 | Порядок фазы A: **картинки + прямые ссылки → Новое → Настройки → локальный поиск → поделиться → бэкапы → публикация** |
| 7 | «🔕 Не следить» в уведомлении — **с подтверждением** (замена последнего ряда кнопок); постер в карточке сериала (§7.4) — **отдельным подшагом позже** |
| 8 | Пересмотр 05.09.2026 (вечер): **источник истины о статусе — страница и расписание, не карточка**; **каталог-first** (поллер заводит все карточки ленты и читает каждый новый тайтл и части франшиз один раз); **поиск отвечает база**, сайт — fallback; **франшиза — основная единица намерения** в выдаче; **тесты на сохранённом HTML**. Новый порядок: постеры полного размера → тесты → каталог → локальный поиск → Новое → Настройки → поделиться → постер в карточке → публикация |

## Хвосты

- Очередь чтения каталога: ~340 страниц по 3 за цикл ≈ 6 ч на старте; дальше 4–6/ч. Если долго — поднять
  `PER_CYCLE_READS`
- Настройки применяются к новым уведомлениям: уже стоящие в очереди уходят по старому времени
- `_site_queries` и лимитеры — в памяти процесса: при второй реплике бота (фаза B) — Redis/UNLOGGED
- Тест `notify_at()` только ручной (psql); в pytest нет базы
- Постер у уже известных страниц появляется, когда страница попадает в ленту (обложка) или при недельном
  обновлении (og:image); до этого уведомление уходит текстом. Бэкфилл не делали — 24 страницы, само дойдёт
- Части франшиз без расписания на сайте и не встречавшиеся в ленте считаются «идущими» → лишние запросы
  на недельном обновлении (с расписанием — уже помечаются завершёнными, 05.09.2026: 10 страниц бэкфиллом)
- Счётчик «уведомлений=N» в логе поллера не учитывает `new_part` (косметика)
- Автодочитывание 3 верхних частей при первом открытии обзора франшизы («ещё не смотрели» вместо «данных нет»)
- Резервный сервер-выход; webhook — фаза B
