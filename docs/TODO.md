# Состояние и план работ

Обновлено: 07.09.2026. Архитектура — [ARCHITECTURE.md](ARCHITECTURE.md), масштаб и UX —
[PRODUCT_AND_SCALE.md](PRODUCT_AND_SCALE.md).

## Работает в проде (@HDRezkaSeriesBot)

Локальный поиск по каталогу (pg_trgm, только выходящие, франшизы одной строкой; «🔍 Искать на сайте» —
fallback) → подписка на сезон или франшизу (обзор состава перед подпиской) → выбор озвучек → расписание
и календарь → 🆕 Новое → ⚙️ Настройки (картинки, тихие часы 23–08, пояс, дайджест, озвучка по умолчанию;
время доставки считает `notify_at()`) → уведомления о серии, озвучке, новой части франшизы (все три пути
проверены end-to-end) → уведомление с постером (фото для одной серии, дайджест для нескольких) и кнопками
«▶ Смотреть S×E» (прямо на серию и озвучку), «🎙 Другие озвучки», «🔕 Не следить» с подтверждением →
карточка сериала с постером и «🔗 Поделиться» (`/start p_<id>`) → завершённость сезона по расписанию и по
тишине (сайт помечает «Завершен» не все); завершённый без франшизы — «🔔 Сообщить о продолжении» →
главное меню 3×2 → защита (лимиты, только путь из ссылки, только личные чаты, глобальный обработчик
ошибок) → Alembic, ротация логов, graceful shutdown, systemd-туннель с iptables.

Правило: **технические сообщения в Telegram не отправляются никогда** — только логи и /stats.

## Решения приняты (05.09.2026, «по рекомендациям»)

| # | Решение |
|---|---|
| 1 | Картинки: **фото** для одной серии, **текстовый дайджест** для нескольких |
| 2 | Главное меню **3×2**: Найти · Мои подписки / 🆕 Новое · Календарь / ⚙️ Настройки · Помощь |
| 3 | **Локальный поиск** (pg_trgm + unaccent), каталог наполняется из ленты; сайт — только fallback |
| 4 | Задержка горячих уведомлений **до часа принимается**; платная рассылка — не раньше 100k MAU и только по жалобам |
| 5 | Тихие часы **включены по умолчанию, 23:00–08:00 МСК**, отключаются в настройках (ночное сообщение хуже утреннего) |
| 6 | Порядок фазы A: **картинки + прямые ссылки → Новое → Настройки → локальный поиск → поделиться → бэкапы → публикация** |
| 7 | «🔕 Не следить» в уведомлении — **с подтверждением** (замена последнего ряда кнопок); постер в карточке сериала (§7.4) — **отдельным подшагом позже** |
| 8 | Пересмотр 05.09.2026 (вечер): **источник истины о статусе — страница и расписание, не карточка**; **каталог-first** (поллер заводит все карточки ленты и читает каждый новый тайтл и части франшиз один раз); **поиск отвечает база**, сайт — fallback; **франшиза — основная единица намерения** в выдаче; **тесты на сохранённом HTML**. Новый порядок: постеры полного размера → тесты → каталог → локальный поиск → Новое → Настройки → поделиться → постер в карточке → публикация |

      Решение 3 ARCHITECTURE.md §7 переписано. Проверено на живой базе: карточка «Соло-кемпинг на двоих»

      сразу при чтении, прошлогодний — когда страница известна боту 30 дней (перерыв между курами короче).
      Текущий год и страницы с расписанием — не трогает; ложный «завершён» снимает первая же серия в ленте.
      Бэкфилл не нужен: прочитанных сериалов без расписания в базе один, и он уже завершён по карточке

      было — 4 старых ушли сразу, до `notify_at()`. Сама функция проверена в 00:54 UTC: тихие часы →

## Резервный сервер-выход — план (не реализовано: нужен второй сервер)

Сейчас один SSH SOCKS-туннель (`deploy/rezka-tunnel.service`) на сервер в Латвии; падает он — сайт
недоступен: поллер пишет «Доступ потерян», бот отвечает «сайт недоступен».

Что нужно от вас: второй VPS в стране, где сайт не блокируют (не дата-центр с забаненной подсетью;
проверка с него: `curl -sI https://rezka-ua.tv | head -1` → 200/403-Anubis, не таймаут), и к нему —
адрес, SSH-порт, пользователь без sudo с `AllowTcpForwarding yes`, ваш публичный ключ в его
`authorized_keys`. Хост-ключ примет `StrictHostKeyChecking=accept-new` при первом подключении.

Как сделать:
1. `deploy/rezka-tunnel@.service` — шаблон с `EnvironmentFile=/etc/rezka-tunnel/%i.env`
   (REMOTE, SSH_PORT, SSH_KEY, LISTEN_PORT); экземпляры `@lv` (= нынешний юнит, порт 1080) и `@backup`
   (порт 1081). iptables-правило в `ExecStartPre`/`ExecStopPost` — то же, с `--dport $LISTEN_PORT`.
   Оба туннеля включены постоянно (`enable --now`).
2. Переключение вручную, без пересборки: в `.env` `HDREZKA_PROXY=socks5h://172.28.0.1:1081`, затем
   `sudo -n docker compose up -d bot poller` (sender к сайту не ходит). Обратно — так же.
3. Автоматика (второй шаг): `HDREZKA_PROXIES=socks5h://172.28.0.1:1080,socks5h://172.28.0.1:1081` и переход
   на следующий прокси при `AccessBlocked` — как перебор зеркал `HDREZKA_BASE_URLS` в `RezkaClient`;
   в лог «Переключаюсь на прокси …», в `/stats` — какой активен.
4. Проверка: `curl -x socks5h://172.28.0.1:1081 -sI https://rezka-ua.tv | head -1` с хоста; после
   переключения в логе поллера «Anubis: пройдено» и обычный «Цикл: …».
