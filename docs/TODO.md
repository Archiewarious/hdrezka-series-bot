## Работает в проде (@HDRezkaSeriesBot)

Локальный поиск по каталогу (pg_trgm, только выходящие, франшизы одной строкой; «🔍 Искать на сайте» —
fallback) → подписка на сезон или франшизу (обзор состава перед подпиской) → выбор озвучек → расписание
и календарь → 🆕 Новое → ⚙️ Настройки (картинки, тихие часы 23–08, пояс, дайджест, озвучка по умолчанию;
время доставки считает `notify_at()`) → уведомления о серии, озвучке, новой части франшизы (все три пути
проверены end-to-end) → уведомление с постером (фото для одной серии, дайджест для нескольких) и кнопками
«▶ Смотреть S×E» (прямо на серию и озвучку), «🎙 Другие озвучки», «🔕 Не следить» с подтверждением →
карточка сериала с постером и «🔗 Поделиться» (`/start p_<id>`) → завершённость сезона по расписанию и по
тишине (сайт помечает «Завершен» не все); завершённый без франшизы — «🔔 Сообщить о продолжении» →
главное меню 3×2 → защита (лимиты, только путь из ссылки, только личные чаты, глобальный обработчик
ошибок) → Alembic, ротация логов, graceful shutdown, systemd-туннель с iptables.

Правило: **технические сообщения в Telegram не отправляются никогда** — только логи и /stats.

## Решения приняты (05.09.2026, «по рекомендациям»)

| # | Решение |
|---|---|
| 1 | Картинки: **фото** для одной серии, **текстовый дайджест** для нескольких |
| 2 | Главное меню **3×2**: Найти · Мои подписки / 🆕 Новое · Календарь / ⚙️ Настройки · Помощь |
| 3 | **Локальный поиск** (pg_trgm + unaccent), каталог наполняется из ленты; сайт — только fallback |

| 5 | Тихие часы **включены по умолчанию, 23:00–08:00 МСК**, отключаются в настройках (ночное сообщение хуже утреннего) |
| 6 | Порядок фазы A: **картинки + прямые ссылки → Новое → Настройки → локальный поиск → поделиться → бэкапы → публикация** |
| 7 | «🔕 Не следить» в уведомлении — **с подтверждением** (замена последнего ряда кнопок); постер в карточке сериала (§7.4) — **отдельным подшагом позже** |
| 8 | Пересмотр 05.09.2026 (вечер): **источник истины о статусе — страница и расписание, не карточка**; **каталог-first** (поллер заводит все карточки ленты и читает каждый новый тайтл и части франшиз один раз); **поиск отвечает база**, сайт — fallback; **франшиза — основная единица намерения** в выдаче; **тесты на сохранённом HTML**. сайте нет → подписаться не на что, а человек хочет узнать о новом сезоне.

      без новой схемы: это обычная подписка `scope='page'` на страницу с `is_finished`. Карточка —
      «🔔 Жду продолжения», кнопка «❌ Больше не ждать»; в «Мои подписки» — «завершён, жду продолжения».
      В локальной и сайтовой выдаче такие тайтлы — строкой «🔔 … · завершён» (до 3, `MAX_WAITING`) → карточка.
      Решение 3 ARCHITECTURE.md §7 переписано. Проверено на живой базе: карточка «Соло-кемпинг на двоих»
- [x] Обнаружение продолжения: `Poller._adopt_waiting` после каждого чтения страницы с франшизой —
      подписки на завершённые части переводятся на франшизу (`subscribe_franchise`), о частях-продолжениях
      (`continuation_parts`: не завершены, не старше ждавшейся по году; непрочитанные дочитываются) уходит
      `new_part` только этому пользователю. Быстрый путь — лента (новый сезон читается с 1-й серии);
      запасной — `refresh_pages` раз в 7 дней перечитывает завершённые страницы с прямыми подписчиками;
      `refresh_franchises` сверяет и франшизы, где есть только «ждущие» (франшизу мог завести бот по ссылке).
      Лог: «ПРОДОЛЖЕНИЕ: франшиза «…» — переведено подписок N, уведомлений M». Живого случая пока не было
- [x] Бэклог апдейтов при перезапуске сохраняется (`drop_pending_updates=False`); `SkipStaleUpdates`
      пропускает сообщения старше 15 минут (в лог). Callback идут всегда: просроченные Telegram отклоняет,
      `on_error` пишет info и не отвечает пользователю

## Проверка после «Жду продолжения» — 06.09.2026 (утро UTC)

- [x] Очередь чтения каталога. Факты: каталог засеян 05.09 23:22 UTC (`pages.created_at`), а не «15 часов
      назад»; поллер читал ровно 3/цикл (≈50/ч, 89 страниц за 1,5 ч), но очередь не убывала — за то же
      время прибыло ~70 страниц: части франшиз из блока (LIFO по `created_at` — читаются первыми) и
      карточки выдачи поиска (36 за один поиск в 00:15). `PER_CYCLE_READS` 3 → 8 (≈140/ч; до 20 запросов
      за цикл при `REQUEST_DELAY=4`). После деплоя в логе «прочитано новых=8»
- [x] Завершённость без расписания: `finished_by_silence()` в `sync_page` — сериал без расписания на сайте,
      год старше текущего, серий в ленте не было 30 дней (`QUIET_DAYS`): двухлетней давности и старше —
      сразу при чтении, прошлогодний — когда страница известна боту 30 дней (перерыв между курами короче).
      Текущий год и страницы с расписанием — не трогает; ложный «завершён» снимает первая же серия в ленте.
      Бэкфилл не нужен: прочитанных сериалов без расписания в базе один, и он уже завершён по карточке
- [ ] Тихие часы и дайджест на живых уведомлениях: с деплоя настроек (05.09 ≈23:20 UTC) уведомлений не
      было — 4 старых ушли сразу, до `notify_at()`. Сама функция проверена в 00:54 UTC: тихие часы →
      05:00 UTC (08:00 МСК), дайджест → 17:00 UTC (20:00 МСК), выключено → now(). Проверить позже:
      `SELECT id, kind, created_at, next_attempt_at, sent_at, status FROM notifications ORDER BY id DESC LIMIT 20;`
      — у ночных `next_attempt_at` = 05:00 UTC и `sent_at` ≈ `next_attempt_at`; лог sender без ошибок
- [ ] «Жду продолжения»: живого случая не было — подписок `scope='page'` на завершённые страницы 0,
      «ПРОДОЛЖЕНИЕ:» в логе поллера нет. Проверить:
      `SELECT sub.user_id, p.title FROM subscriptions sub JOIN pages p ON p.id = sub.page_id WHERE sub.scope = 'page' AND p.is_finished;`
      и `docker compose logs poller | grep ПРОДОЛЖЕНИЕ`

## Резервный сервер-выход — план (не реализовано: нужен второй сервер)

Сейчас один SSH SOCKS-туннель (`deploy/rezka-tunnel.service`) на сервер в Латвии; падает он — сайт
недоступен: поллер пишет «Доступ потерян», бот отвечает «сайт недоступен».

Что нужно от вас: второй VPS в стране, где сайт не блокируют (не дата-центр с забаненной подсетью;
проверка с него: `curl -sI https://rezka-ua.tv | head -1` → 200/403-Anubis, не таймаут), и к нему —
адрес, SSH-порт, пользователь без sudo с `AllowTcpForwarding yes`, ваш публичный ключ в его
`authorized_keys`. Хост-ключ примет `StrictHostKeyChecking=accept-new` при первом подключении.

Как сделать:
1. `deploy/rezka-tunnel@.service` — шаблон с `EnvironmentFile=/etc/rezka-tunnel/%i.env`
   (REMOTE, SSH_PORT, SSH_KEY, LISTEN_PORT); экземпляры `@lv` (= нынешний юнит, порт 1080) и `@backup`
   (порт 1081). iptables-правило в `ExecStartPre`/`ExecStopPost` — то же, с `--dport $LISTEN_PORT`.
   Оба туннеля включены постоянно (`enable --now`).
2. Переключение вручную, без пересборки: в `.env` `HDREZKA_PROXY=socks5h://172.28.0.1:1081`, затем
   `sudo -n docker compose up -d bot poller` (sender к сайту не ходит). Обратно — так же.
3. Автоматика (второй шаг): `HDREZKA_PROXIES=socks5h://172.28.0.1:1080,socks5h://172.28.0.1:1081` и переход
   на следующий прокси при `AccessBlocked` — как перебор зеркал `HDREZKA_BASE_URLS` в `RezkaClient`;
   в лог «Переключаюсь на прокси …», в `/stats` — какой активен.
4. Проверка: `curl -x socks5h://172.28.0.1:1081 -sI https://rezka-ua.tv | head -1` с хоста; после
   переключения в логе поллера «Anubis: пройдено» и обычный «Цикл: …».

## Хвосты

- Очередь каталога после деплоя: через ~3 ч `SELECT count(*) FROM pages WHERE page_refreshed_at IS NULL`
  должен быть около нуля; иначе смотреть «Очередь чтения»/«не читается … цикла подряд» в логе поллера
- `finished_by_silence`: через месяц сверить на живых данных — прошлогодние части без расписания
  помечены, выходящие (последняя серия < 30 дней) нет: `SELECT title, year, is_finished, last_event_at
  FROM pages WHERE content_type='series' AND NOT EXISTS (SELECT 1 FROM schedule sc WHERE sc.page_id=pages.id)`
- Настройки применяются к новым уведомлениям: уже стоящие в очереди уходят по старому времени
- `_site_queries` и лимитеры — в памяти процесса: при второй реплике бота (фаза B) — Redis/UNLOGGED
- Тест `notify_at()` только ручной (psql); в pytest нет базы
- Постер у уже известных страниц появляется, когда страница попадает в ленту (обложка) или при недельном
  обновлении (og:image); до этого уведомление уходит текстом. Бэкфилл не делали — 24 страницы, само дойдёт
- «Жду продолжения» через ссылку в боте: `sync_page` из бота франшизу заводит, но ждущих не переводит —
  их подберёт суточная сверка `refresh_franchises` (до 24 ч). Не проверено на живом случае
- Автодочитывание 3 верхних частей при первом открытии обзора франшизы («ещё не смотрели» вместо «данных нет»)
- Резервный сервер-выход — план выше; webhook, вторая реплика, Redis — фаза B
