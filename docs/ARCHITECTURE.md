### 1.2. Независимое подтверждение (чужой парсер)

`HdRezkaApi` v11.2.3 на PyPI (12 781 символов документации): моделирует `translators`, `seriesInfo` **по озвучкам**, `episodesInfo` — то есть независимо от меня пришёл к тому же: серии существуют **на уровне озвучки**, а не тайтла. Франшизу и расписание эта библиотека не использует — это находки только из первичного источника. Пакет `hdrezka` в npm не существует (404).

### 1.3. Telegram Bot API (официальные документы)

| Факт | Источник |

| aiogram 3 имеет встроенную интеграцию webhook через aiohttp | `docs.aiogram.dev` |

### 1.4. PostgreSQL (официальная документация)

- `FOR UPDATE SKIP LOCKED` — прямо описан как средство «избежать конкуренции блокировок при нескольких потребителях очереди-таблицы».
- Удаление старых данных партициями «намного быстрее массового DELETE и полностью избегает накладных расходов VACUUM».

### 1.5. Железо

Oracle (ARM Neoverse-N1, 2 ядра, 12 ГБ, 85 ГБ свободно) — в 2–4 раза быстрее латвийского VPS; SHA-256 аппаратный (×4 на PoW). Латвия — только сетевой выход.

## 2. Что это меняет

Первая версия схемы считала, что «тайтл = страница» и «серия = (сезон, номер)». Факты F1, F7, F11 ломают оба допущения:

1. Подписка на страницу аниме — это подписка **на один сезон** (F1). Без связи через франшизу подписчик ТВ-4 никогда не узнает о ТВ-5.
2. «Вышла серия» **без озвучки** — неоднозначное событие (F7). Для «Слизи» это неважно (все озвучки в один день), для «Ван-Пис» — разница в 750 серий.
3. Раздел не говорит, сериал это или фильм (F11) — фильмы попадали в выдачу поиска.

Хорошая новость: сайт сам отдаёт и франшизу (F3), и расписание (F4) — **эвристики по названиям не нужны**.

## 3. Модель данных

### 3.1. Сущности

```
users            — пользователи Telegram
franchises       — группы частей, как их отдаёт сайт (F3); ключ = минимальный id части (F15)
pages            — страницы сайта; page.franchise_id — принадлежность к франшизе
voices           — озвучки страницы (F5)
episodes         — серия доступна хотя бы в одной озвучке (из блока обновлений, F13)
episode_voices   — серия доступна в конкретной озвучке (из блока обновлений, F13)
schedule         — расписание выхода (F4)
subscriptions    — подписка на СТРАНИЦУ или на ФРАНШИЗУ, опционально с фильтром озвучек
notifications    — исходящая очередь (outbox)
meta             — время последнего обхода и разбора блока обновлений
```

### 3.2. Схема

```sql
CREATE TABLE users (
    id            BIGINT PRIMARY KEY,               -- telegram user id
    username      TEXT,
    is_active     BOOLEAN NOT NULL DEFAULT TRUE,    -- FALSE после 403 «bot was blocked»
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    blocked_at    TIMESTAMPTZ
);

CREATE TABLE franchises (
    id              SERIAL PRIMARY KEY,
    key_hdrezka_id  INTEGER NOT NULL UNIQUE,     -- минимальный id среди частей: не меняется при добавлении новых
    name            TEXT NOT NULL,               -- общий префикс названий либо название самой ранней части
    refreshed_at    TIMESTAMPTZ,                 -- когда последний раз сверяли состав
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE pages (
    id                 SERIAL PRIMARY KEY,
    hdrezka_id         INTEGER NOT NULL UNIQUE,     -- data-id, стабилен между зеркалами
    title              TEXT NOT NULL,
    url                TEXT NOT NULL,
    year               TEXT,
    section            TEXT,                        -- series / animation / cartoons / films
    content_type       TEXT,                        -- 'series' | 'film' | NULL (страницу ещё не читали) — F11
    is_finished        BOOLEAN NOT NULL DEFAULT FALSE,           -- «Завершен» в карточке, ИЛИ по расписанию: все серии
                                                                 --  вышли, будущих нет, последняя > 60 дн., ИЛИ по тишине
                                                                 --  (06.09.2026): расписания нет, год старше текущего, серий
                                                                 --  в ленте не было 30 дн. (сайт помечает не все; лента
                                                                 --  снимает флаг только серией новее известной)
    last_season        INTEGER,
    last_episode       INTEGER,
    default_translator INTEGER,                     -- из initCDNSeriesEvents — F5
    poster_url TEXT,                                -- og:image страницы; до её чтения — обложка из ленты (F16)
    poster_file_id TEXT,                            -- file_id в Telegram после первой загрузки: одна загрузка на сериал (F17)
    franchise_id       INTEGER REFERENCES franchises(id) ON DELETE SET NULL,
    page_refreshed_at  TIMESTAMPTZ,
    last_event_at      TIMESTAMPTZ,
    created_at         TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX pages_ongoing   ON pages (page_refreshed_at) WHERE NOT is_finished;
CREATE INDEX pages_franchise ON pages (franchise_id);

CREATE TABLE voices (
    page_id        INTEGER NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    translator_id  INTEGER NOT NULL,
    name           TEXT NOT NULL,
    PRIMARY KEY (page_id, translator_id)
);

CREATE TABLE episodes (
    id             SERIAL PRIMARY KEY,
    page_id        INTEGER NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    season         INTEGER NOT NULL,
    episode        INTEGER NOT NULL,
    first_seen_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (page_id, season, episode)               -- идемпотентность события «серия появилась»
);

CREATE TABLE episode_voices (
    episode_id     INTEGER NOT NULL REFERENCES episodes(id) ON DELETE CASCADE,
    translator_id  INTEGER NOT NULL,
    seen_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (episode_id, translator_id)
);

CREATE TABLE schedule (
    page_id    INTEGER NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    season     INTEGER NOT NULL,
    episode    INTEGER NOT NULL,
    title      TEXT,
    air_date   DATE,
    aired      BOOLEAN NOT NULL DEFAULT FALSE,
    PRIMARY KEY (page_id, season, episode)
);

CREATE TABLE subscriptions (
    id            SERIAL PRIMARY KEY,
    user_id       BIGINT  NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    scope         TEXT    NOT NULL,                     -- 'page' | 'franchise'
    page_id       INTEGER REFERENCES pages(id)      ON DELETE CASCADE,
    franchise_id  INTEGER REFERENCES franchises(id) ON DELETE CASCADE,
    voice_filter  INTEGER[],                           -- NULL = любая озвучка
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    CHECK ((scope = 'page' AND page_id IS NOT NULL AND franchise_id IS NULL)
        OR (scope = 'franchise' AND franchise_id IS NOT NULL AND page_id IS NULL))
);
CREATE UNIQUE INDEX subs_user_page      ON subscriptions (user_id, page_id)      WHERE page_id IS NOT NULL;
CREATE UNIQUE INDEX subs_user_franchise ON subscriptions (user_id, franchise_id) WHERE franchise_id IS NOT NULL;
CREATE INDEX subs_by_page      ON subscriptions (page_id);        -- fan-out
CREATE INDEX subs_by_franchise ON subscriptions (franchise_id);   -- fan-out

CREATE TABLE notifications (                        -- outbox: транзитная таблица, не архив
    id               BIGSERIAL PRIMARY KEY,
    user_id          BIGINT NOT NULL,
    kind             TEXT   NOT NULL,               -- episode | voice | new_part
    ref_id           BIGINT NOT NULL,               -- episodes.id / episode_voices.episode_id / pages.id
    status           TEXT   NOT NULL DEFAULT 'pending',  -- pending | sending | sent | failed
    attempts         INTEGER NOT NULL DEFAULT 0,
    next_attempt_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    error            TEXT,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    sent_at          TIMESTAMPTZ,
    UNIQUE (user_id, kind, ref_id)                  -- пользователь получает событие один раз
);
-- Частичный индекс: только «горячая» часть очереди, остаётся маленьким при любом объёме.
CREATE INDEX notifications_queue ON notifications (next_attempt_at, id) WHERE status = 'pending';

CREATE TABLE meta (
    key        TEXT PRIMARY KEY,
    value      TEXT NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 3.3. Почему так

**Два вида подписки: на страницу и на франшизу (решение от 05.09.2026).** Подписка на страницу —
серии одного сезона/шоу. Подписка на франшизу — серии **любого** выходящего сезона плюс **появление
любой новой части**: фильм, OVA, спин-офф, документалка. Состав берётся из блока франшизы (F3):
он симметричен и стоит на каждой части, включая фильмы, поэтому новая часть сама сообщает,
куда относится — сравнение названий не используется вообще (F15: они и не совпадают).

Ключ франшизы — минимальный `hdrezka_id` среди частей: он не меняется при добавлении новых.
Имя — общий префикс названий («О моём перерождении в слизь»), а если его нет — название самой
ранней части («Игра престолов»). Имя нужно только для показа.

Как ловим новые части: раз в сутки — **одна** страница на каждую франшизу с подписчиками (блок
одинаковый на всех частях, достаточно любой); новый id в блоке → читаем эту часть (тип, название)
→ уведомление «Новая часть франшизы …». Стоимость — число франшиз с подписчиками запросов в сутки.
Ускоритель через ленту: неизвестная страница с первыми сериями (e ≤ 2) или с названием, похожим
на имя франшизы, читается сразу — но это оптимизация, а не опора.

Известное следствие широты франшизы на сайте: подписчик «Игры престолов» получит и серии
making-of «Дом, который построили Драконы». В первой версии не фильтруем.

**Два уровня «вышла серия».** `episodes` — первое событие о серии в блоке обновлений, в любой озвучке. `episode_voices` — каждая озвучка серии: блок сообщает её в том же событии (F13). По умолчанию `voice_filter = NULL`: уведомление при первом появлении серии, подписанное озвучкой — для «Слизи» это ровно то, что нужно (F7). Кто смотрит только в Дубляже — выбирает озвучку и получает уведомление, когда серия есть **именно там**; выбрано две — два уведомления, каждое со своей озвучкой (решение 10.09.2026).

**Отложенных проверок озвучек больше нет.** До 10.09.2026 их вела таблица `voice_checks` через ajax плеера (F6) с растущим интервалом. Блок обновлений перечисляет события по каждой озвучке, включая дозвучки старых серий, поэтому проверки и таблица удалены.

**`content_type` заполняется со страницы.** Пока страницу не читали — `NULL`; в выдаче поиска фильмы отсекаются по признаку из карточки (`info=''`, F11), а после первого чтения страницы — по `initCDNMoviesEvents` навсегда.

**`notifications` — транзит, не журнал.** `UNIQUE(user_id, kind, ref_id)` защищает от дублей пока строка живёт; повторное событие по той же серии невозможно из-за `UNIQUE` в `episodes`. Отправленные строки удаляются через 7 дней — таблица не растёт. Если понадобится постоянная история доставки — отдельная таблица с партициями по месяцу (документация PostgreSQL: сброс партиции быстрее массового DELETE). На 1 пользователе и на 100 000 схема одна и та же; меняется только политика очистки.

## 4. Процессы и потоки данных

```
                    ┌────────────────────────── Латвия (только сетевой выход, SSH-туннель) ─┐
                    │                                                                         │
 главная: блок     ─┤──► poller (ровно один экземпляр, pg_advisory_lock)                       │
 «Обновления»       │      │  1. блок: 1 запрос / 3 мин → episodes, episode_voices (F13)       │
 страницы тайтлов ──┤      │  2. новая серия на непрочитанной странице → 1 запрос до           │
                    └──────┤     уведомления: pages, franchise, voices, schedule               │
                           │  3. сверка франшиз — сутки, страницы с подписчиками — 7 дней       │
                           │  4. очередь чтения каталога                                        │
                           ▼                                                                   │
                      PostgreSQL ── fan-out одним INSERT … SELECT из subscriptions ──► notifications
                           │                                                                   │
              ┌────────────┴────────────┐                                                      │
              ▼                         ▼                                                      │
      bot (N реплик, webhook)     sender (N реплик, SKIP LOCKED, token bucket 25/с)             │
      поиск, подписки, /my,       429 → пауза retry_after; 403 blocked → users.is_active=false │
      кнопки suggestions          агрегация: несколько событий одному человеку → одно сообщение │
```

### 4.1. Poller

Упрощено 10.09.2026 после ревью: один источник событий, одна очередь чтения, одна проверка здоровья.

- **Singleton по построению**: `pg_try_advisory_lock(<константа>)` при старте; второй экземпляр ждёт.
- **Источник событий — только блок «Обновления» на главной** (F13). Один запрос за цикл. Курсора нет: блок хранит
  неделю по дням, каждое событие `(id, сезон, серия, озвучка)` сверяется с базой, повторный разбор ничего не дублирует,
  простой поллера до недели ничего не теряет. Ленты разделов (F8, F9 опровергнут) и проверки озвучек через плеер (F6)
  удалены: блок сообщает и серию, и озвучку.
- **Новизну решают только записи бота** (`classify_update`): запись о серии есть — новая озвучка; старше всех записей
  страницы — новая серия; записей нет — новая, только если событие свежее (сегодня или вчера), иначе дозвучка задним
  числом и записывается молча. Поля страницы (`last_episode`) на это не влияют: их пишут чтение страницы в поллере и в
  боте и карточки поиска, и 10.09.2026 чтение, запущенное самим событием, превращало премьеру в «старую».
- **Затравка при подписке**: у подписанной страницы без записей текущая последняя серия записывается как известная
  (дата 1970 — не попадает в «🆕 Новое» и в проверку здоровья), иначе первая дозвучка старой серии сошла бы за новую.
- **Чтение до уведомления**: новая серия на непрочитанной странице → сначала страница (франшиза, озвучки), потом
  рассылка. Лимит 10 чтений за цикл; не хватило — событие откладывается, блок хранит его неделю. Незнакомая озвучка на
  странице, прочитанной больше суток назад, → перечитать список озвучек (не больше половины лимита).
- **Озвучки** (`match_voice`): полное имя с уточнением в скобках, язык берётся из флажка на странице
  («FanVoxUA (Украинский)»). Запасные шаги — «Субтитры» ↔ «Оригинал (+субтитры)», латиница в скобках у транслитерации,
  начало имени до пробела. Неоднозначно — не угадываем: 10.09.2026 отбрасывание скобок сливало разные озвучки
  на 65 страницах.
- **Уведомления**: подписчикам с «любой» озвучкой — о серии, с подписью первой озвучки; с фильтром — по одному на
  каждую выбранную озвучку, с её названием. Первая серия части франшизы — «новая часть» для подписанных на другие её
  части; фильмы и спин-оффы — «новая часть» по суточной сверке франшиз, только недавние (год не старше прошлого).
- **Перечитывание страниц с подписчиками**: выходящие — раз в 12 часов, завершённые («жду продолжения») — раз в
  неделю. Оттуда расписание (F4), озвучки и статус. Заодно **подстраховка**: если список серий на самой странице
  новее всех записей бота, серия записывается и уходит уведомление (подписчикам «любой» озвучки и озвучки по
  умолчанию — список серий на странице принадлежит именно ей). Сработавшая подстраховка пишет в лог `warning`:
  значит, блок обновлений событие потерял, и это надо разобрать.
- **Здоровье** (`app/health.py`) — не «цикл завершился», а «события идут»: цикл не старше 20 мин, блок разобран не
  позже 20 мин назад, новая серия не позже 12 ч назад. Одна проверка для `/stats` и healthcheck контейнера поллера.
- **Бюджет запросов** (глобальный лимитер 1 запрос / 4–6 с):

| Поток | Запросов/час | Основание |
|---|---|---|
| Блок обновлений на главной, раз в 3 мин | 20 | F13 |
| Чтение страниц ради событий | 0–10, в пике до 120 | новые тайтлы и незнакомые озвучки |
| Refresh страниц с подписчиками: выходящие раз в 12 ч, завершённые раз в 7 дней | ≈1 на выходящую страницу в сутки | 9 выходящих страниц на 12.09.2026 |
| Сверка франшиз с подписчиками, раз в сутки | ≈1 | число франшиз |
| Очередь чтения каталога, по 8 за цикл | 4–6, в пике ~140 | новые тайтлы из блока и поиска |
| **Итого** | **≈30–60** | не зависит от числа пользователей |

- **Политика при потере доступа**: 403 или заглушка → экспоненциальная пауза (2 → 4 → … → 30 мин), ERROR в лог.
- **Anubis**: cookie живёт 30 дней (F12), PoW решается заново только по истечении.

### 4.2. Sender

- Забирает пачку `FOR UPDATE SKIP LOCKED` → можно запускать несколько реплик без координации (документация PostgreSQL прямо описывает этот сценарий).
- Token bucket 25 сообщений/сек (лимит ~30, F-Telegram), **не более 1 сообщения/сек одному пользователю**: события для одного человека, накопившиеся за окно в 60 секунд, склеиваются в одно сообщение («Вышли: Слизь 4×21, Ван-Пис 22×1176»). Это одновременно снимает проблему «пять уведомлений про одну серию».
- 429 → спим `retry_after`, строка обратно в `pending` с `next_attempt_at`. 403 «blocked by user» → `users.is_active = false`, все его pending → `failed`. Прочие ошибки → до 5 попыток с ростом интервала.
- Очистка: `DELETE FROM notifications WHERE status IN ('sent','failed') AND sent_at < now() - interval '7 days'` раз в сутки.
- **Настройки пользователя (06.09.2026).** Тихие часы и дайджест не проверяются в sender'е: SQL-функция
  `notify_at(tz, quiet_from, quiet_to, digest_hour)` вычисляет `next_attempt_at` при постановке в очередь;
  при смене настроек `reschedule_pending()` пересчитывает и уже стоящие в очереди (06.09.2026).
  `users.lang` (ru / uk / en) — язык текстов бота и уведомлений (`app/i18n.py`); новому — из Telegram
  (три `INSERT … SELECT` в `service.enqueue_*`). Sender читает только `users.photos` (фото или текст).
- **Формат (05.09.2026).** Одно событие пользователю → `sendPhoto` с постером, подписью и кнопками «▶ Смотреть S×E»
  (`url#t:{translator}-s:{s}-e:{e}`, F18), «🎙 Другие озвучки», «🔕 Не следить» (с подтверждением). Два и больше →
  текстовый дайджест с кнопками «▶» внизу. Постер качается **напрямую с CDN, без туннеля** (F17), первый раз
  грузится байтами, `file_id` из ответа → `pages.poster_file_id`: дальше одна и та же картинка не скачивается
  и не загружается. Нет постера, не скачался, Telegram не принял — уведомление уходит текстом с теми же кнопками.

### 4.3. Bot

- **Сейчас** — long polling (один экземпляр, ноль инфраструктуры). **При росте** — webhook: aiogram 3 умеет из коробки через aiohttp; нужен домен и 443 на Oracle (security list + iptables). Переключение — конфигом, код обработчиков не меняется. Причина перехода не «производительность» (пользователи пишут боту редко), а возможность нескольких реплик: `getUpdates` допускает только одного потребителя.
- Бот **не ходит на сайт ни при чём, кроме поиска** — и поиск идёт через тот же глобальный лимитер клиента.
- Кэш поиска: одинаковые запросы за 10 минут → из `meta`/памяти, чтобы 100 человек, набравших «ван пис» после выхода серии, не сделали 100 запросов к сайту.

### 4.3.1. Защита бота (05.09.2026)

Главный дефицит — единственный рабочий IP к сайту, поэтому лимитируются действия,
ведущие к запросу на сайт, а не сообщения вообще. Реализация — `app/bot/guard.py`.

| Угроза | Мера |
|---|---|
| Бот как открытый прокси: ссылка на чужой хост уходила через туннель | из ссылки берётся **только путь**, хост всегда наш (`_PATH_RX`) |
| Один пользователь сжигает бюджет запросов к сайту | поиск/ссылка: 6 в минуту, 60 в час на пользователя |
| Спам кнопками / `/my` | 30 в минуту, 600 в час (только база) |
| Мусор во вводе | обрезка до 100 символов, удаление управляющих и невидимых символов |
| Группы, каналы, другие боты | обрабатываются только личные чаты от людей; остальное — молча |
| Не-текст (стикеры, фото) | подсказка, под тем же лимитом |
| Очередь за лимитером вешает ответы | потолок ожидания сайта 25 с → «попробуйте позже» |
| Раздувание базы подписками | не больше 100 подписок на пользователя |
| Необработанная ошибка | глобальный `errors`-обработчик: в лог, пользователю нейтральный ответ |
| Бэклог апдейтов после простоя | `delete_webhook(drop_pending_updates=True)`, только `message` и `callback_query` |

Гигантские сообщения отсекает сам Telegram (лимит 4096 символов текста) — это не наша задача.

### 4.4. Надёжность

| Угроза | Мера |
|---|---|
| Потеря БД | `pg_dump` ежедневно в отдельное хранилище + снапшот тома; хранить 14 дней; раз в месяц проверять восстановление |
| Поллер умер или события перестали идти | `app/health.py`: цикл старше 20 мин, блок обновлений не разобран 20 мин, новых серий нет 12 ч → `/stats` и healthcheck контейнера поллера (`docker compose ps`). До 10.09.2026 проверялось только «цикл завершился», и неработающий курсор пять дней выглядел здоровьем. **В Telegram технические сообщения не отправляются никогда** (правило от 05.09.2026) |
| Туннель упал | systemd `Restart=always`; проверка здоровья видит это как «цикл не завершался» |
| Бан IP | пауза + алерт; запасной план — второй fetcher на другом IP, клиент перебирает список прокси |
| Смена вёрстки | блок обновлений разобран в 0 событий → ERROR в лог и «блок не разбирается» в проверке здоровья; `check_access` в один шаг |
| Дубли уведомлений | три `UNIQUE`: episodes, notifications, subscriptions + `SKIP LOCKED` |
| Два поллера | advisory lock |
| Утечка токена | `.env` 600, не в git; `/revoke` в BotFather |

## 6. Поведение бота (уроки со скриншота)

**Поиск (решение от 05.09.2026: только онгоинги).** Из выдачи убираются фильмы (F11) и завершённые
тайтлы — без кнопки «показать завершённые». Показывается не больше 5, кнопка несёт состояние:
`Слизь [ТВ-4] · 4 сезон, 21 серия`. На «Слизь» останется одна кнопка.
Ссылка на завершённую страницу → отказ: «Этот сезон уже вышел целиком, подписаться нельзя».
Следствие: случай «новая озвучка старого сезона» сознательно не поддерживается.

**После подписки.** «Подписал: Слизь [ТВ-4]. Сейчас 4×21. Следующая — 12 сентября (F4).
Озвучка: любая» и кнопки: [Выбрать озвучку] [Вся франшиза (8 частей)] [Отписаться].
Кнопка франшизы показывается только если частей больше одной. Подписка на франшизу заменяет
подписку на её страницу — в `/my` одна строка, дублей уведомлений нет (`UNIQUE` в notifications).

**Ссылка** → карточка с кнопкой «➕ Подписаться на этот сезон» (решение от 05.09.2026: подписка
только по нажатию, не автоматически). Карточка приходит после одного запроса к сайту; флаг
«завершён» отдаёт только лента, поэтому он проверяется в фоне и при необходимости карточка
перерисовывается. Для фильма или завершённого сезона кнопки подписки нет — только франшиза, если есть.

**Новая часть франшизы.** «🆕 Новая часть франшизы Мастера меча онлайн: Безответная бабочка (фильм, 2026)» — только подписчикам франшизы.

**/my.** Название · текущая серия · «следующая: дата» · кнопка отписки.

**«Кнопка не работает» — по логам работала.** В 06:11:12–06:11:33 бот обработал шесть нажатий (update 924058474–479), каждое за 23–52 мс, без единой ошибки. Единственной обратной связью был всплывающий тост `cb.answer(...)`, который на десктопе легко не заметить, а само сообщение с кнопками не менялось. Это дефект интерфейса, не логики. В новой версии ответ на нажатие — всегда редактирование сообщения (кнопка превращается в «✓ Подписан»), чтобы результат был виден без тоста.
